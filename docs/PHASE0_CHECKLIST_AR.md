# المرحلة 0 — قائمة التحقق الميداني (قبل أول عميل)

هذه الاختبارات **لا يمكن تنفيذها إلا على هاتف حقيقي وعلى GitHub الفعلي**؛ الاختبارات الآلية (`run_tests.bat`) تغطي المنطق لكنها لا ترى
شاشة أندرويد ولا مكتبات الهاتف ولا البناء. خصّص لها يوماً أو يومين، ودوّن النتيجة أمام كل بند. التعليمات المختصرة بالأسفل تقول **ماذا ترسل لي** لأقرّر الخطوة التالية.

## أ) تهيئة ومعدّات
- هاتفان على الأقل: **ضعيف** (أندرويد 8–10، رام ≤ 2 جيجا) و**متوسط** (أندرويد 12+). أضف جهازاً ثالثاً إن أمكن لاختبار «الاستعادة على جهاز آخر».
- حساب GitHub بأسرار التوقيع الأربعة (راجع «النشر والتوقيع» في README_AR.md) و`public_keys.py` المملوء.
- بعد أول بناء ناجح: سجّل «بصمة شهادة التوقيع (SHA-256)» من سجل الخطوة **Verify APK** وضعها في Variables باسم `ANDROID_CERT_SHA256`.

## ج) قرار Pillow (أهم بند يخصّ الأداء)
1. فرع تجريبي: في `pyproject.toml` فعّل السطر المعلّق `dependencies = ["flet==0.28.3", "pillow"]`.
2. شغّل البناء. **إن فشل** عند تثبيت الحزم: ارجع للتعطيل (التطبيق يعمل بدونها) وأخبرني بنص الخطأ.
3. **إن نجح**: ثبّت وافتح تشخيص الجهاز ← يجب أن يظهر «معالجة الصور (Pillow) ✓ + الإصدار». ثم أضف صورة كاميرا: حجمها المخزّن (في تقرير التشخيص: ملفات المرضى) يجب أن يكون بضع مئات كيلوبايت لا ميغابايتات.
4. للبيانات القديمة: «تشخيص الجهاز ← تحسين الصور الموجودة».
5. ادمج الفرع فقط بعد نجاح 1–4 على الهاتف الضعيف.

## د) ما أحتاجه منك للحكم
- نص «تقرير التشخيص» من كل هاتف (زر «تصدير تقرير التشخيص»؛ لا يحوي أسماء مرضى).
- جدول البند ب بعد ملئه، مع لقطة شاشة لأي ✗.
- سجل خطوة Verify APK (البصمة) ونتيجة تجربة Pillow.
